# Instructions for coding agents

## Mandatory acceptance reconciliation

All coding agents must follow [Updating issue acceptance after a pull request](CONTRIBUTING.md#updating-issue-acceptance-after-a-pull-request). On every observed merge notification, post-merge check-in or resumption of related work, verify the live PR/merge evidence and automatically update the acceptance checklist in each issue body advanced by the authorized work, including partial delivery using `Refs`. Do not wait for a reminder. Check only fully satisfied criteria, keep partial/unvalidated items unchecked, and add or update a linked evidence note with remaining gates. Preserve unrelated content and other contributors' progress, reconcile concurrent edits, avoid duplicate notes, and read back the issue to verify the checklist and state. Incomplete issues stay open; closure without merge is not delivery. Report exact blockers instead of silently skipping reconciliation. If handing off an open PR, record this step as pending for the next observed merge or resumed work; inactive agents do not continuously monitor GitHub.

Before working in this repository, read and follow [CONTRIBUTING.md](CONTRIBUTING.md) and [.github/copilot-instructions.md](.github/copilot-instructions.md). Their contribution rules, architecture/security invariants, validation requirements, and issue/PR ownership workflow apply to all coding agents, not only GitHub Copilot.

Require authenticated GitHub CLI (`gh`) access for the ownership workflow, subject to the session's supported tools and authorization boundaries. When a human asks you to take on an issue, automatically assign that issue and every PR produced by the session to that human, link the actual session branch in GitHub Development or report the specific linking blocker, and verify the assignments and links. Existing-branch linking requires a verified API/tool or a verified manual UI action; `gh issue develop` is not an arbitrary existing-branch linking command. For PRs without an issue, issue assignment and branch-to-issue linking are N/A, but human PR assignment remains required. Resolve ambiguous identity with the user; preserve existing assignees and app-managed branches/worktrees. Use `Closes` in the PR body only for fully completed acceptance criteria; automatic issue closure occurs on merge into the default branch, not on closing an unmerged PR. Follow the detailed workflow and authorization boundaries in the linked instructions, and report blockers rather than claiming incomplete steps succeeded.
